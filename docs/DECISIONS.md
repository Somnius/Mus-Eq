# Decisions log (date, choice, reason). Open items live in `OPEN_QUESTIONS.md`.

- 2026-11-06 **Server in Rust**; Android client in Kotlin. Fits the owner, cross-compiles to Linux/Windows/macOS and Android, and the reusable part of cliamp (a Go terminal player) is only subprocess glue.
- 2026-11-06 **cliamp is an optional existing client, not a base.** Its station and yt-dlp logic is a reference (MIT notice if copied). A cliamp provider for MusEq is a phase 4 nice-to-have, not an exit criterion.
- 2026-11-06 **Greek radio list: Tray-FM** by Constantinos (Unlicense), copied to `data/stations/trayfm-stations.txt`. Stream liveness is checked in phase 2.
- 2026-11-06 **No WorkOS / hosted auth.** Token auth.
- 2026-11-07 **Auth: one owner bearer token from phase 1** (applies the Q9 default); `/v1/health` open.
- 2026-11-07 **Network: bind localhost by default, LAN/Tailscale is the owner's network** (applies the Q11 default).
- 2026-11-07 **External stations are passed through, never proxied.** `/v1/radio` is for library and live stations.
- 2026-11-07 **One `job` table** (kinds scan|fetch|tag|fingerprint) instead of separate job tables.
- 2026-11-07 **Transcoding: ffmpeg in the image; in-process Opus is an option measured at the start of phase 5.**
- 2026-11-07 **Phase 1 is split**: 1a server core (curl-checkable, CI green), 1b Webamp client and session, then phase 2.
- 2026-11-07 **Desktop shell stays open (Q13)**, browser first; decided at phase 4.
- 2026-11-07 **Phase 1a data shortcuts:** `artist`/`album` are text columns on `track`, one track per file, ids are SQLite integers exposed as strings, codec = file extension. Proper tables and fingerprints arrive with dedupe (phase 3).
- 2026-11-07 **Playlist edits:** items are removed/reordered by replacing the whole list (`PUT /v1/playlists/{id}/items`).
- 2026-11-07 **Server refuses to start without a token** (min 16 characters); it never prints it.
- 2026-11-07 **Browser auth is a cookie** (HttpOnly, SameSite=Strict) next to the bearer token, because `<audio>`, skin URLs and the WebSocket can't send headers. CSRF guard on cookie-authenticated mutations; WebSocket Origin check.
- 2026-11-07 **Session = the playing client reports, commands go to it.** Avoids every open tab starting playback.
- 2026-11-07 **Skins are stored raw and parsed in the browser**; the server never unzips them.
- 2026-11-07 **No read-only token yet**; widgets use the owner token. Revisit when per-device tokens arrive.
- 2026-11-07 **Web client is served by the server** (same origin); Vite proxies in development.
- 2026-11-07 **Process: each phase ends with tests, two independent reviews, doc updates and the owner's green light; commits are local per step and pushes happen at phase completion.**
- 2026-11-07 **Cookie = random server-side session id**, not the token (review finding): logout revokes it; login attempts are rate limited.
- 2026-11-07 **A moved or renamed file keeps its row** (matched by sha256 when its old path is gone), so playlists don't lose it.
- 2026-11-07 **Web client uses Webamp's private `__onStateChange` hook** to notice state changes. If a Webamp upgrade removes it, session reporting stops (the 10 s interval report still fires). Pin the Webamp version and re-run the smoke test on upgrades.
- 2026-11-07 **Logo:** a bold white M on a near-black rounded tile with a stepped orange equalizer underline (assets/logo.svg, also used as the favicon). Picked by the owner from 25 candidates; hand-written SVG, no text or external assets.
- 2026-11-07 **Projects we can't copy (no licence, GPL, AGPL, incompatible) are re-implemented, not copied:** we learn their behaviour from docs, public APIs and use, write our own behaviour notes, and build our own Rust version from those notes. Public specs (OpenSubsonic, MusicBrainz, AcoustID) can be implemented directly. MIT/Apache/Unlicense code may be used with its notice. Ideas borrowed are credited here. See `docs/COMPARISON.md`.
- 2026-11-07 **Stations play in the browser through a plain audio element, straight from the station** (Webamp's loader needs CORS, which most streams lack). Plain-HTTP streams are blocked on HTTPS pages, so the Play button is disabled there with a note.
- 2026-11-07 **Q3 answered: the Omarchy radio** is https://radio.cliamp.stream/omarchy/stream (128 kbps MP3, CORS open; the http address redirects). Site https://radio.omarchy.org/ (playlist page /playlist), podcast feed https://api.riverside.com/hosting/1i59HjrN.rss. Added to `data/stations/museq-stations.txt`; the server now accepts several comma-separated seed lists. Podcasts and now-playing from the site are later ideas, not planned yet.
- 2026-11-07 **Omarchy plugins:** no existing plugin speaks our API, so we write a first-party widget later in its own repository (findings in `docs/PLUGINS.md`). MIT plugins can be reused with notice; GPL ones (Omafin, Omamich, Celestune Bar, BearWave) are ideas only. We install no third-party plugin on the owner's machine without asking, because plugins run unsandboxed.
- 2026-11-07 **Webamp's `pause()` and `play()` press the player's buttons** (pause toggles, play restarts), so the web client only calls them when the status says it matters. Found when the independent test run failed on the remote play-station check.
- 2026-11-07 **Fingerprints are computed in-process in Rust** (`rusty-chromaprint`, MIT) instead of shelling out to `fpcalc`: no extra binary in the image. Opus is unsupported by Symphonia 0.6.1, so Opus files are marked unsupported for fingerprinting for now. AcoustID compatibility of the output is unverified.
- 2026-11-07 **Duplicates: one track can own several files.** Accepting a duplicate group merges tracks in SQLite only (the files stay on disk, playlist entries are re-pointed to the kept track). Nothing is ever deleted; this applies the Q8 and Q12 defaults (server-side first, corrections in SQLite only).
- 2026-11-07 **Phase 3d (fetch) was blocked on Q2** until the owner allowed building it behind the flag (superseded by the entries below).
- 2026-11-07 **Accepted metadata corrections live in SQLite only** (Q12 default): the audio files are never rewritten, and a corrected track keeps its tags across rescans. Candidates from MusicBrainz and AcoustID are stored and never applied automatically.
- 2026-11-07 **One shared rate limiter per outside service** (MusicBrainz about 1 request per second, AcoustID about 3 per second) so two jobs can't double the rate; only fake servers are used in tests and CI.
- 2026-11-07 **Playlist extension uses the local library and the genre tag only** (no network, no downloads): same genre, a new artist each time. Style similarity beyond the genre tag is a later idea.
- 2026-11-07 **Duplicate comparisons are stored, not recomputed.** The scale test showed the duplicate list was quadratic (449 s at 20,000 files). The fingerprint job now compares new files against the library and stores the pairs; the list reads them.
- 2026-11-07 **Opus is decoded with libopus** (the `opus` crate, built from source, cmake needed); Symphonia stays for every other format. Checked against ffmpeg sample for sample.
- 2026-11-07 **Thresholds kept: MAX_SCORE 2.0, MIN_COVERAGE 0.8, 4 s length window**, after real-music tuning (a six-point gap between true and false matches). A partial copy is not offered as a duplicate (window), by default.
- 2026-11-07 **Fetch is off by default and needs a typed acknowledgement.** `MUSEQ_FETCH=on` alone does nothing; `MUSEQ_FETCH_ACK` must carry the exact sentence `i-have-read-the-terms-and-fetch-only-what-i-may-store`, so that enabling it is a deliberate act after reading the services' terms, not a copied flag. Q2 is answered as "the code exists, the owner decides per deployment".
- 2026-11-07 **yt-dlp is the owner's own binary, given as an absolute path** (`MUSEQ_FETCH_YTDLP`, must exist). Nothing is looked up on `PATH` and the image does not ship it, so the server cannot be tricked into running a different tool and the version is the owner's choice.
- 2026-11-07 **yt-dlp never sees the pasted text.** The link is parsed into a video id or Spotify track id, and the only address handed to the tool is a `watch?v=<id>` the server built; the process is started without a shell, in its own process group, with a size cap and a deadline.
- 2026-11-07 **Cookies are copied per run and never written back.** `MUSEQ_FETCH_COOKIES` must be a mode-600 file; it is used only after a sign-in wall, as a private copy in the run's work folder that is deleted with it. The original is never passed to the tool directly, because yt-dlp's documented `--cookies` option also saves its cookie jar back to that file.
- 2026-11-07 **Spotify links are resolved from the public track page's meta tags** (`og:title`, `music:musician_description`, `music:album`, `music:duration`), not through an API, an account or Deezer (Q6 default: link only). A page that lacks them is an error, never a guess. Deezer is dropped from the plan.
- 2026-11-07 **Matcher rules for the YouTube Music search:** title word-overlap at least 0.6 after folding, duration within 5 s when both are known, the artist must appear in the channel or title, uploads whose title adds a version word (live, remix, karaoke, cover, slowed, nightcore, instrumental, reverb, sped, acoustic, demo, edit, mashup, 8d) the request did not contain are rejected, and the artist's auto-generated "- Topic" channel gets a bonus, because it is the label's upload of the studio recording. When nothing qualifies the job fails and names the closest candidate.
- 2026-11-07 **Fetched tags come from the source, not the file.** The downloaded file carries no useful tags, so title, artist and album from the Spotify page (or yt-dlp's info) are written to the track row and marked corrected, and provenance (source URL, video id, tool version, matched title and channel) is stored in its own table. No secret is ever stored.
- 2026-11-07 **Licence (Q14): MIT OR Apache-2.0**, the Rust convention, for the server, web client and Android app. Chosen over Apache-2.0 alone (stronger notice and patent terms, but a narrower audience) and over AGPL-3.0-or-later (which would stop a closed hosted fork but deters contributors and packagers); the one question that would flip it to AGPL is whether a closed, modified, paid hosted copy is something to prevent. The recipient picks either licence, so the Apache-only protections (NOTICE carry-forward, patent grant) apply only when they pick Apache. Contributions are inbound=outbound under the same two licences, with a DCO sign-off and no CLA. `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE` and `docs/THIRD_PARTY.md` (generated by `scripts/gen-third-party.py`) are in the repository root. Not a legal opinion; to confirm with a lawyer if money or a dispute is likely: how the container image meets ffmpeg's licence if it is published, the MPL-2.0 source duty for release binaries, and where rusty-chromaprint comes from. Still to do: per-file SPDX headers (optional), a `cargo deny` licence check in CI, a Gradle licence report for the Android app.
